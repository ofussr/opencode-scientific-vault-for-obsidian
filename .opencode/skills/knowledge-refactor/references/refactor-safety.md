# Refactor Safety

A refactor changes information architecture, not scientific evidence. Make the smallest structural change that clearly improves retrieval and synthesis.

- Do not split solely to increase note count or because a source has multiple sections. Require a durable, independently useful scientific topic supported by substantive evidence.
- Do not merge distinct topics merely because they concern the same material. Check whether they answer different scientific questions and need different evidence or conditions.
- Keep all moved claims traceable to their original source IDs and pages. Preserve conflicting source-specific findings.
- Treat translations as parallel renderings of the same claims, not as new evidence. Preserve formulas, units, citations, uncertainty, and link targets across both language blocks.
- Do not overwrite human prose wholesale. Map existing content before moving it, preserve its meaning, and avoid unrelated stylistic edits.
- Do not delete an old file automatically. If it becomes redundant after a split, preserve its useful overview and update links; deletion requires a separate explicit user request.
- Do not modify source PDFs, manifests, or intermediate extraction claims as part of changing note topology, except to update the refactor work record.
