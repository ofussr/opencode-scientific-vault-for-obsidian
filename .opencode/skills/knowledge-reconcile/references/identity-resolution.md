# Identity Resolution

Similarity is not identity.

Check in this order: exact note title; normalized punctuation/case; chemical formula versus common/systematic name; abbreviation versus expanded name; existing YAML aliases; close semantic candidates found by content search; direct inspection of candidate notes.

Update an existing note when the scientific object is the same and the new source adds another property, condition, measurement, interpretation, source-specific result, or corroborating evidence for an existing proposition. A matching proposition is not a reason to discard a new source: deduplicate claims, not provenance. Skip only evidence from a source ID already integrated for that claim, unless the reprocessing yields a previously unrecorded detail.

Keep a separate note when the topic has enough independent content and represents a reusable distinct level such as a specific phase, growth mechanism, synthesis route, measurement method, material system/phase diagram, or property domain. Link broader and narrower notes only when meaningful.

Prefer adding a useful alias over creating a duplicate. Do not add every textual variant.

If identity cannot be established confidently, do not merge automatically. Record `UNRESOLVED_IDENTITY` and leave the knowledge base unchanged until resolved.
